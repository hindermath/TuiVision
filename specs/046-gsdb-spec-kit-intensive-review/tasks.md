## Ausfuehrungsregeln / Execution Rules

- Aufgaben werden in ID-Reihenfolge ausgefuehrt. Es gibt bewusst keine Parallelmarker: kanonisches JSON, Projektionen, Validator-Testprojekt, Evidence, Version, Statistik, Lifecycle, Run-State und Delivery-State sind gemeinsame oder kausal gekoppelte Writer. / Tasks execute in ID order. There are intentionally no parallel markers because canonical JSON, projections, the validator test project, evidence, version, statistics, lifecycle, run state, and delivery state are shared or causally coupled writers.
- Vor jedem einzelnen `dotnet build` oder `dotnet test` wird genau einmal der manuelle Buildzaehler in `Directory.Build.props` erhoeht und derselbe Aufruf mit Zaehler, Version, Commit und Zweck im Build-Ledger von `specs/046-gsdb-spec-kit-intensive-review/pr-evidence.md` erfasst. One increment covers exactly one invocation.
- Produkt-, Runtime-, Public-API-, XML-, Dependency-, Paket-, Projekt-, Solution-, Beispiel-, Workflow-, Provider-Setting-, Secret-Rotations-, Finding-Abhilfe- und historische Quellaenderungen sind verboten. Es werden keine GitHub Issues, Folge-Intakes, Folge-Branches oder Folge-Features aus Findings erzeugt. / Product, runtime, public API, XML, dependency, package, project, solution, example, workflow, provider-setting, secret-rotation, finding-remediation, and historical-source changes are prohibited. No GitHub issues, follow-up intakes, follow-up branches, or follow-up features are created from findings.
- Erlaubte Schreibziele sind die Feature-Artefakte, das datierte GSDB-Evidence-Verzeichnis, `docs/security/README.md`, genau ein test-only Validatorfile mit kleinen Fixtures im bestehenden Drivers-Testprojekt, die erforderlichen Versions-/Statistik-/Lifecycle-Nachweise sowie autorisierte Delivery-/Retrospektivmetadaten. Runner-eigener Zustand wird nur durch den Runner geschrieben. / Allowed write targets are feature artifacts, the dated GSDB evidence directory, `docs/security/README.md`, exactly one test-only validator file with small fixtures in the existing Drivers test project, required version/statistics/lifecycle evidence, and authorized delivery/retrospective metadata. Runner-owned state is written only by the runner.
- Ein `Open`- oder `FollowUp`-Ergebnis ist bei vollstaendigen Pflichtfeldern zulaessig. Unbelegte positive Claims, erfundene Findings, Inventarluecken, Scope-Verstoesse oder Gate-Luecken blockieren den Lauf. / An `Open` or `FollowUp` result is acceptable when all required fields are complete. Unsupported positive claims, invented findings, inventory gaps, scope violations, or gate gaps block the run.
